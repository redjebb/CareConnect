# Тестови доказателства

Резултати от последното изпълнение (виж и GitHub Actions).

## Модулни тестове – `npm test` (24 теста)
| Област | Какво се доказва |
|---|---|
| Разстояние (Haversine) | София–Пловдив ≈ 130–140 км; симетрия; нулево разстояние |
| Валидация | ЕГН (10 цифри + контролна цифра и реална дата), телефон, имейл, ограничение на бележка |
| SOS маршрутизация | Сигналът отива към диспечера на съответното посещение; `null`, ако няма кого да уведомим |
| Оптимизация на маршрут | Най-близките спирки първо; маршрутът никога не е по-дълъг от първоначалния; спирки без координати остават в края |
| Аналитика | Доставки, порции, проблеми, успеваемост, уникални клиенти; празни данни дават нули (не NaN) |
| Пропуснати посещения | Само минали, неотчетени посещения |
| Офлайн запис | „synced“ при потвърждение, „queued“ без връзка, грешка се връща веднага, късна грешка се докладва |

## Тестове на правилата за сигурност – `npm run test:rules` (25 теста, емулатор)
- Анонимен потребител и потребител без профил не четат нищо.
- Не може да се присвои роля (MASTER_ADMIN/MANAGER) чрез собствен профил.
- Покана: валиден токен → успех; грешен токен, друга роля, чужд шофьор, чужд имейл, вече използвана покана → отказ; токенът не се чете от поканения.
- Само MASTER_ADMIN кани мениджъри.
- Шофьор: чете само свои клиенти/график; променя само подписи, check-in и бележка (≤ 500 знака); не чете регистър (ЕГН), потребители, администратори; не създава и не трие клиенти; смени/сигнали/доставки само със своя `driverId`.
- Мениджър управлява клиенти, график, шофьори; не създава администратори и не променя роли.
- Непосочени колекции са затворени дори за MASTER_ADMIN.

## Сквозни тестове – `npm run test:e2e` (7 сценария, Chrome срещу демо емулаторите)
Анонимен достъп → вход; грешна парола → съобщение; диспечер вижда графика, бележки и „Аналитика“; диспечерът няма секция „Мениджъри“; главният администратор я има; шофьорът вижда само своя маршрут с бележка за достъп и не вижда чужд клиент; шофьорът не може да отвори админ панела.

## Ръчни сценарии (чеклист за защитата)
| № | Сценарий | Очакван резултат |
|---|---|---|
| 1 | Вход като диспечер, добавяне на клиент с бележка „етаж 3, вдясно“ | Клиентът е в регистъра |
| 2 | Добавяне в график към шофьор | Бележката е попълнена автоматично |
| 3 | Вход като шофьор | Вижда само своите посещения, синя бележка „Достъп“ |
| 4 | Промяна на бележката от шофьора | При следващо планиране е обновена |
| 5 | Изключване на интернет → „Доставено“ + подписи | Съобщение „запазено, ще се синхронизира“; при връзка лентата изчезва |
| 6 | „Проблем / SOS“ | Инцидент в системата и имейл до диспечера |
| 7 | „Аналитика“ | Графика, шофьори, проблеми, пропуснати посещения |
| 8 | Опит за влизане с неактивиран акаунт | Достъпът е ограничен |
